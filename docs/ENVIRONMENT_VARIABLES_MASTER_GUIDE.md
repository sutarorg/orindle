# Environment variables master guide

**Audited against source on:** 2026-11-08 UTC. This inventory uses exact names read from `app/`, `lib/`, `middleware.ts` and `next.config.ts`; `.env.example` must remain synchronized with this list.

## Variables specifically checked for but not present in code

- **Resend:** no `RESEND_API_KEY`, `RESEND_FROM_EMAIL` or Resend SDK use exists in the current application source. Authentication mail is delegated to Supabase Auth’s configured email provider. Resend requires a separate SMTP integration/configuration before its API key belongs in this project. Do not add a key now and assume it sends mail.
- **R2 endpoint/public URL:** the S3 endpoint is constructed from `R2_ACCOUNT_ID`; there is no `R2_ENDPOINT` or public base URL variable. The app expects a private bucket and signed URLs.
- **Dodo price IDs:** the checkout code passes Dodo `product_id` in a product cart and validates fixed minor-unit amount variables. It does not read `DODO_PRICE_*_ID`. Confirm Dodo’s current product/recurring price model in its dashboard before setup; do not invent environment names or IDs.
- No `DATABASE_URL`, `AUTH_SECRET`, or `RESEND_*` variable is read by this Next app.

## Safe local validation command

Run `npm run check:env` from the repository root. It loads the local Next.js environment file and reports only variable names/status, never credential values. Missing local configuration is expected before provider setup; `npm run check:env -- --strict` fails when core app/Supabase values are absent, while `npm run check:env -- --all` also requires all OpenRouter, R2 and USD Dodo test settings. This checks presence/format only; it does not authenticate to providers or verify a key.

## Secret handling rules

1. Only `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` and public app/site origins are safe for browser exposure.
2. Keep Supabase service-role, OpenRouter, Dodo, webhook and R2 keys out of frontend code, Git, logs, screenshots and chat.
3. Use separate test credentials in Development/Preview and production credentials only after owner approval.
4. Revoke/rotate a value immediately if it may have been committed, shared or captured in a screenshot.
5. Changes to Vercel environment variables require a fresh deployment to reach running builds/functions.
